## Rules & preferences for this project

The following source notes are retained in full because they contain the project’s decisions, rules, creative direction, delivery constraints, and known technical guardrails.

- The project is a static-export marketing/product site shipped on GitHub Pages, with the active V2 live at `https://gitteromri-ux.github.io/vj-magic-site-v2/` and the original V1 live at `https://gitteromri-ux.github.io/vj-magic-site/`.
- **V1 preserved, V2 active** — the user wanted two links rather than overwriting the first build; V2 was created as a separate repo so the V1/Alpha site remains untouched.
- **Live camera as the core selling moment** — the V2 homepage treats the camera-driven engine as the “beating heart,” starting with a demo clip and camera-permission gate, then moving the live feed into a persistent picture-in-picture card with scroll-triggered effect changes.
- **Software features over market framing** — the site was redirected away from market-size, competitor, team, and DIY-cost content toward product functionality, feature depth, and contact/customer conversion.
- **Interactive modules demonstrate the product** — V2 includes interactive surfaces for VJ Launchpad, multicam camera feeds, live effects, phone-as-camera, QR photo/slideshow flow, pro productions, templates, AI effect generation, 100+ effects, How It Works, Solutions, and Pro pages.
- **Presentations are part of the product story** — the latest V2 update added a homepage presentations/slideshows section for PowerPoint conversion, image upload, and phone QR submission, and removed the MagicTV page and links.
- **V2 is active but paused after June 17** — GitHub activity shows the active V2 repo last pushed on 2026-06-17 after the presentations/PPTX/phone-QR feature, with no newer commits in the 2026-06-20 to 2026-06-22 connector window.
- **Defensive asset loading for Pages** — V1 fixed a client-side crash by avoiding a throwing `useLoader` texture load at `/logo/logo-chrome.png` without the GitHub Pages base path.
